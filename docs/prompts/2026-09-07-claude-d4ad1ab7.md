Short answer: yes for the two hard parts, no for "all". The package is a fit for handle resolution and transcripts, and the transcript contract in AGENTS.md already anticipates "an explicitly approved package". It would be a downgrade for the feed.

**What it is.** `youtubei.js` is a client for InnerTube, the private API YouTube's own web and mobile apps use. Unauthenticated for public data, no API key. Version 18.0.0 was published 2026-08-13, so it's actively maintained. It ships a dedicated `youtubei.js/cf-worker` entry point, and its three dependencies (a protobuf runtime, a compression library, a JS parser) have no Node-only requirements. That's the strongest runtime story of any YouTube library I know of for workerd.

**Where it earns its place**

- **Handle resolution.** InnerTube has a proper resolve-URL endpoint. That replaces reading an HTML canonical tag, which is exactly the kind of thing YouTube breaks by changing markup.
- **Transcripts.** The library uses the same transcript endpoint the YouTube transcript panel uses. The direct caption-track approach has been getting less reliable from server IPs over the last couple of years, so this is where a maintained library saves the most pain.

**Why not the feed.** RSS is public, has been stable for over a decade, and gives us title plus the recent episodes in one request with no library. Swapping that for an undocumented API is more surface area for no gain. Keep `rss.ts` as is.

**Risks to weigh honestly**

- **Size.** 16 MB unpacked on disk. The runtime bundle is a fraction of that, but Workers cap scripts at 3 MB compressed on the free plan and 10 MB on paid, and a big bundle adds cold-start time. Must be measured.
- **Bot detection.** YouTube challenges datacenter IPs, and Cloudflare egress is datacenter. This risk exists for the hand-rolled approach too, and the library does not make it go away. One nuance matters for testing: plain `wrangler dev` runs workerd on your laptop, so outbound requests leave from your home IP and would hide the problem. The spike has to run with `--remote` or a real workers.dev deploy.
- **Churn.** Undocumented API, frequent major versions. Someone else fixes breakage, but a broken version blocks ingestion until we bump. That trade is usually worth it for a two-person tool.
- **Terms of service.** Same posture as scraping the watch page. Only the Data API is clean, and that was rejected earlier today.
- **Rules.** Hard rule 2 needs one more clause naming InnerTube via this package. Everything else in AGENTS.md already accommodates it.

**Recommendation.** Approve `youtubei.js` for a spike before building on it. The spike must prove five things under `wrangler dev --remote`: it imports and initializes in workerd, it resolves a real `@handle`, it returns a transcript for a known captioned video from a Cloudflare IP, the built bundle size fits the plan you're on, and cold start stays reasonable.
