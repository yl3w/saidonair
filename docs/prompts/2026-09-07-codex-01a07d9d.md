[Spec: delivery dependency](/Users/bhaskar/workspace/media-digest-assistant/docs/specs/home-read-experience.md:386)

2. **High — “Following” can contradict the user’s actual choice.**  
   Request outcomes are derived only from Registry request/channel state. Someone can be automatically followed, explicitly unfollow, and still see “Following” under Your requests. A completed automatic-follow handoff also does not guarantee a follow was inserted: existing unfollow tombstones are deliberately preserved.  
   **Recommendation:** incorporate current User DO follow state, or use historical wording such as “Approved” with a separate current Follow/Following control. [Spec: outcome composition](/Users/bhaskar/workspace/media-digest-assistant/docs/specs/home-read-experience.md:350)

3. **Medium — Completion does not refresh the rest of Home.**  
   Only the request list polls, and actions refresh their own rows. When automatic following completes, the request can say “Following” while Followed, Available, and the digest remain stale. Manual follow/unfollow has the same cross-section dependency.  
   **Recommendation:** specify which sections refresh after each action or request transition, including how existing NEW markers are preserved. [Spec: refresh behavior](/Users/bhaskar/workspace/media-digest-assistant/docs/specs/home-read-experience.md:535)

4. **Medium — Fetch ordering does not make unread totals match NEW markers.**  
   Followed counts cover all processed episodes; the digest covers only 24 hours. Ten older unread episodes and two recent ones produce “12 unread” alongside two NEW items, regardless of request order. Expanding to seven days also refetches items already marked read.  
   **Recommendation:** label the count “unread total,” define NEW as a snapshot for the current visit, and remove the claim that ordering guarantees matching counts. This preserves the agreed read-on-return behavior. [Spec: unread claim](/Users/bhaskar/workspace/media-digest-assistant/docs/specs/home-read-experience.md:147)

5. **Medium — Empty-state copy misdiagnoses ordinary situations.**  
   Following every available channel makes the filtered Available list empty, but the UI says “The catalog is empty.” A user whose follows are all unavailable fits neither of the spec’s two digest conditions cleanly. The seven-day view still says “Nothing new since yesterday.”

[Spec: empty states](/Users/bhaskar/workspace/media-digest-assistant/docs/specs/home-read-experience.md:141)
