5. **[PM / Designer] Digest inclusion, response shape, and displayed time disagree.**  
   The PRD still selects by publication time ([PRD.md:233](/Users/bhaskar/workspace/media-digest-assistant/docs/PRD.md:233)), while M3 selects by first availability ([m3-ingestion.md:51](/Users/bhaskar/workspace/media-digest-assistant/docs/specs/m3-ingestion.md:51)); the revised `Episode` sketch omits `summaryAvailableAt` ([home-read-experience.md:604](/Users/bhaskar/workspace/media-digest-assistant/docs/specs/home-read-experience.md:604)). The UI also displays only publication age, so a month-old episode first summarized today looks incorrectly placed in “Today’s digest.” Standardize on `summaryAvailableAt`, showing “summarised X ago” as the primary digest timestamp.

6. **[Engineering] Vector cleanup is not durable.**  
   Cleanup failures are merely logged ([m3-ingestion.md:111](/Users/bhaskar/workspace/media-digest-assistant/docs/specs/m3-ingestion.md:111)), and the spec assumes a future attempt will clean leftovers ([m3-ingestion.md:198](/Users/bhaskar/workspace/media-digest-assistant/docs/specs/m3-ingestion.md:198)). After successful publication or terminal recovery, there may never be another attempt. Persist cleanup work independently—such as a cleanup ledger reconciled by cron—or relax the one-generation invariant.

   The Home API table still calls itself the contract on `main` ([home-read-experience.md:518](/Users/bhaskar/workspace/media-digest-assistant/docs/specs/home-read-experience.md:518), [home-read-experience.md:803](/Users/bhaskar/workspace/media-digest-assistant/docs/specs/home-read-experience.md:803)), while the implementation plan states runtime work has not started ([m3-ingestion-plan.md:7](/Users/bhaskar/workspace/media-digest-assistant/docs/specs/m3-ingestion-plan.md:7)). Separate shipped behavior from target behavior and remove every obsolete current-contract statement.

## Medium-severity findings

8. **[Engineering / PM] Initial discovery is ambiguous and race-prone.**  
   The feature spec says the first successful feed read consumes initial selection, while the plan says an empty successful read does not ([m3-ingestion.md:43](/Users/bhaskar/workspace/media-digest-assistant/docs/specs/m3-ingestion.md:43), [m3-ingestion-plan.md:158](/Users/bhaskar/workspace/media-digest-assistant/docs/specs/m3-ingestion-plan.md:158)). Additionally, `startDiscovery` decides `initial` versus `scheduled` before the Registry transaction ([m3-ingestion-plan.md:281](/Users/bhaskar/workspace/media-digest-assistant/docs/specs/m3-ingestion-plan.md:281)). Overlapping Start/cron calls can both choose `initial`. Derive kind, eligible entries, actual inserts, and `discovered_count` atomically in the Registry.

9. **[PM / Engineering] Timed-out episodes can remain counted as waiting.**  
   `waiting` is defined solely from the latest attempt’s status ([m3-ingestion.md:169](/Users/bhaskar/workspace/media-digest-assistant/docs/specs/m3-ingestion.md:169)). A final caption/live attempt may remain `waiting` while publication becomes `failed` or replacement recovery ends, double-counting the episode indefinitely. Require both `latestAttempt.status = waiting` and an active `recovery_mode`, or define a terminal status for the final attempt.

10. **[Designer] Retry enablement is contradictory.**  
    Several overview sections disable Retry for any running attempt ([PRD.md:412](/Users/bhaskar/workspace/media-digest-assistant/docs/PRD.md:412)), while the detailed design enables it after one hour to invoke inline reconciliation ([m3-ingestion-plan.md:355](/Users/bhaskar/workspace/media-digest-assistant/docs/specs/m3-ingestion-plan.md:355)). Standardize every surface on disabled under one hour; enabled afterward with visible attempt age and an inline explanation if the Workflow is still active.
